# S5 运行、暂停与数据保存

本阶段仅补齐固定 DA/FHS5 拓扑的 U 初态留出运行，复用已绑定的 O 运行。实验配置、数据去重、统计单位见同目录冻结执行合同；不要将本阶段当作新盲确认。

## 进度和阶段

实时入口：`results/supplement/initialization-ablation-v1/progress.md`。机器可读状态：同目录 `progress.json`（生成），`replay-progress.json`（单独重放），`pipeline-status.json`（后台流程）。按真实单位分别显示百分比，不将生成完成当成论文结果完成。

后台流程由 `tools/pipeline_supplement_initialization.py` 串行衔接：两进程生成 → 单独输入重建和票据重放 → 检查所有结果收据 → 完整文件字节清单 → Git 索引/提交字节核对 → 推送并核对远端提交。核验通过后的结果仍需四臂配对统计及图表，不自动入稿，也不展开新的实验。

诊断日志、上传收据在 `results/diagnostics/S5-initialization-pipeline-v1`。若推送失败，保留所有数据及本地提交，停止流程；不重跑模拟。数据完整上传后最终状态是 `verified-simulation-uploaded-awaiting-four-arm-statistics`，不是“论文实验全部完成”。

## 安全暂停和恢复

需要暂停时，让助手创建输出目录内的 `PAUSE` 文件。生成和重放均在不超过100请求的小段成功保存后退出。确认后台、生成、重放锁全部正常释放，以及进程退出，再关机；不要直接删除锁或强杀进程。暂停不是自动上传，要求上传时另做静止断点快照。

恢复需核对旧进程确实不存在、源码/配置/运行时哈希保持一致；将 PAUSE 及意外停机残留锁移入诊断留档后，重新启动后台流程。已有通过的小段和重放收据不重算，崩溃时只有未原子提交的小段可能重做。正常运行时不得修改哈希绑定的 common/preparer/executor/checker 或冻结核心。

运行环境：Python 3.12.14 / Windows，固定 bundled Python；环境变量 PYTHONPATH=`E:\second-doc-runtime;E:\second`，PYTHONIOENCODING=`utf-8`，PYTHONDONTWRITEBYTECODE=`1`。必须在 `E:\second` 启动，后台窗口隐藏。不得在论文一目录执行、使用云服务器或调整已冻结参数。

每个输入保存请求、路由根种子、初始状态、来源映射；每个新段保存全部请求结局、路由搜索信息、耗竭坐标、完整状态链、首次事件、服务数量/金额和代价。失败之后仍模拟至 H，原始细节足以支持后续合法重分析，无需重复长模拟。

## 时间估计边界

preflight.json 给出6个真实输入的段耗时和剩余请求量。较大规模仅抽取一个 BA 父图/轨迹，不能覆盖所有路由搜索难度；这只是计算量级估计，不能保证完成时刻。生成采用两个进程；单独重放另算，文件核验和 GitHub 上传也另算。以后只按新完成请求与实测耗时更新阶段估计，不报告虚假的项目总体百分比。
