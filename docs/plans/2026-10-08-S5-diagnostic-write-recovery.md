# S5 进度写入失败的授权恢复

2026-10-08 用户明确同意修复并恢复。前次停止原因是 Windows 拒绝替换某个 `run-progress/<uid>.json`，不是模拟或验证发现科学错误。错误发生前该小段科学文件已经原子保存；恢复仍须逐段检查哈希、状态链与请求编号，不能把运行收据当作完整重放。

使用单独 v3 操作层，不修改冻结 common、executor、科学核心、参数、原 v2 调度器或原 supervisor。新 supervisor 保持原预检清单原字节，额外绑定 v3 源码及测试；上传清单将包含这些额外文件。

v3 子进程一次只执行原 v1 的一个不超过100请求的小段。只对本单元进度 JSON 的原子替换增加至多10秒的短暂权限冲突重试；数据只序列化、写入和 fsync 一次，重试同一个临时文件的 rename。科学文件写入不受此重试影响，原模拟不重新执行。其他 I/O 异常、持续权限失败仍停止并保留文件。

错误日志、旧 PAUSE、停止时进度以及失败临时进度文件均须保存字节和 SHA-256。确认相关进程已经退出、没有未解决锁后才可将 PAUSE 与诊断临时文件归档解除暂停。任何科学 chunk/result 都不得删除。

验证包括：短暂/持续拒绝替换、无关 I/O、精确路径隔离、原 scientific save 的错误传播、两个真实并发进度写入者，以及原 executor 对比 v3 的实际模拟、100请求断点恢复和已保存段不重算。实际恢复另按元数据选择此前失败单元，校验原段并新增最多一个小段，然后交给原单独重放检查器；这不替代全量核验。

继续本机两个 worker，完成生成后运行原单独重放并将字节核验结果提交 GitHub。四臂统计仍须等待完整核验和上传门槛，补充分析不视为新盲确认。静态 v2 进度中的调度器标签保持原实现含义；实际 v3 覆盖由独立绑定及 supervisor 命令明确记录。
