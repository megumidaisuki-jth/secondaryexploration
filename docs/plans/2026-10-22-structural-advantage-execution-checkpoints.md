# 结构稳健性补充实验：首轮执行与暂停合同

用户已授权开始补充实验并要求随时暂停恢复。本轮首先执行原设计第0阶段：隔离的工程试运行，不把试运行输出作为新的确认样本。

## 当前启动范围

- 配置：`configs/supplement/structure-robustness-engineering-v1.json`。
- 输入：60/120节点、ER/BA/SBM各1个新父图，共6个；独立工程种子命名空间。
- 构造每个FHS源的8个预定二元候选，检查连通性、参与预算与正余额。
- 运行FHS3、FHS5及FHS5的原参照、替代随机参照、训练金额/双向金额参照。
- 每臂运行均匀请求和方向反转请求各240笔；奇数参与预算分别保留上下两侧。
- 需求加权构造只接触4条独立训练请求（各1440笔）。本阶段没有宣称已选出B★，没有进行正式终点推断。
- 1个低于正常优先级的工作进程，不停止、不改写本机已经运行的其他实验。

第0阶段完成后保留工程门槛；不会由该脚本自动进入A/B/C。A的完整输入可行性、精度规划、候选选择实现与冻结仍需后续完成。这是按既定阶段顺序开始执行，不是减少正式样本量。

## 暂停和恢复

在项目目录的PowerShell运行：

```powershell
.\tools\structure-robustness-control.ps1 status
.\tools\structure-robustness-control.ps1 pause
.\tools\structure-robustness-control.ps1 resume
```

用户也可直接在对话中要求暂停/恢复。首次启动用同脚本的`start`。

暂停请求立即写控制文件，当前小段完成后停止。**等待状态为`paused-safe-checkpoint`且`runner_lock_live=false`，或工程阶段已完成且无活跃锁，再关机。** 小段最多10笔请求，但一笔路径搜索可能很慢，因此不承诺固定秒数内退出。

每小段以临时文件、刷新、原子替换保存压缩数据和校验哈希；包含初末余额、逐请求路径与接受/拒绝、首次事件、累计服务和成本、请求绝对编号、前一小段哈希。随机票据按绝对请求编号生成。状态页是进度提示，真正的恢复依据是完整小段链。

恢复先校验代码、配置、运行时、输入与已存小段，不重新模拟已提交段。意外断电后最多重算尚未原子提交的小段。临时残件不视为完成结果，不自动删除。错误暂停不会被普通resume清除，必须先定位问题，保留原始证据。

运行锁是操作系统持有的文件字节锁，不单凭PID或锁文件存在判断；进程退出即释放，不需手工删除陈旧锁。重复启动会因独占锁失败，不会同时写同一目录。恢复脚本不接管其他任务。

## 验证和界限

新增测试覆盖连续/分段完整路径及余额一致、断点字节复用、暂停不计算、篡改/截断拒绝、版本变更拒绝、独占锁、奇偶预算、候选可重现、训练输入接口及独立余额/无路径核验；同时回归原S5断点测试。

每段除沿用R0核心自检，还用独立字典算术检查资金守恒、路径连续性和拒绝请求的残余可达性。它不是完整独立科学盲审，也不替代未来对新选择器、R1/R2及B模块的核验。

工程时域只有240，且与其他实验共享本机；其耗时不能直接承诺正式1440请求阶段的完成时间。工程输出保留逐段耗时，后续估时需说明状态复杂度、并发资源、核验开销与不确定范围。

结果和进度目录：`results/supplement/structure-robustness-engineering-v1`。每阶段核验后按既有归档规则保存到GitHub；运行中的目录不当作完成结果上传。
